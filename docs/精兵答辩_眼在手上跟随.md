## 0. 一分钟电梯陈述

我做的是一台桌面六轴 + 腕部深度相机的**眼在手上视觉伺服**样机：人移动目标时，臂保持「相机光心对准目标 + 规定距离」（产品名：**喷枪瞄准**）。

价值不在臂本身，而在三件事：

1. **把现场故障翻译成可验收需求**（绕圈、串口超时、换物体推倒重来）。  
2. **用软件架构解耦感知与控制**（目标总线 + 独立解算器）。  
3. **把 AI Agent 嵌进工程闭环**（术语表 / ADR / 实机排障），而不是只聊天生成碎片代码。

这对应民机智能制造里信息岗最常做的事：多传感器集成、OT 友好控制、可插拔算法、可远程可复现的研发运维。

## 1. 问题定义与成功标准

### 1.1 业务类比（对评委）

民机现场大量任务可抽象为：

> **末端携带传感器或工具，相对工件/特征保持稳定位姿关系**  
> （检测头对缝、涂胶/喷涂枪对轨迹点、协作臂对人持示教件……）

桌面样机把问题缩成可日更迭代的微场景：**人持目标移动 → 臂跟着「瞄准」**。

### 1.2 产品成功标准（必须讲清）

| 术语 | 含义 | 刻意不包含 |
|---|---|---|
| **喷枪瞄准** | 光心落在目标上；距离按目标：标定板 ~20 cm，充电头 ~10 cm | 抓取闭合、法兰轴穿心、「正对平面」进主回路 |
| **跟随** | 追到瞄准后进入保持；目标离开滞回再追 | 仅启动 Hub、仅拖动示教 |
| **保持 (Hold)** | 停止笛卡尔追击，维持位姿 | 与串口层 `hold_servo` 不是同一件事 |
| **CDC 静默** | 非追击阶段尽量少写 USB | 拔插 USB 不当日常手段 |

### 1.3 为何先定标准再写代码

早期若没有「喷枪瞄准」这一定义，团队会在「要不要锁 J4」「要不要追姿态」上无限分叉。  
**选型原则**：主任务尽量低维（平移对准 + 距离），冗余自由度交给二次任务或锁轴减负，而不是把所有自由度塞进主误差。

## 2. 系统总览

### 2.1 数据流（技术路线总图）

```
腕部 RealSense (RGB + 对齐深度)
        │
        ├─► ArUco 检测 ──► /tracking/board_*
        └─► 充电头检测 ──► /tracking/charger_*

         tracking_target_mux（follow_source）
```

人机入口：Tracking Hub（检测指示、开始跟随、回初始、收起、六轴拖动）。

## 3. 分步技术路线、备选方案与选型原因

下面每一步统一格式：**背景现象 → 目标 → 备选 → 选定方案与路线 → 为何选它 → 实现要点 → 智能制造映射**。

---

### 步骤 A｜运动与通信底座：谁有权写电机

#### 背景现象

- 同时存在 Fibre 硬件节点与 CDC 路径时，**抢同一 USB 口**。  
- 杀桥接进程或断电时电机会**瞬间失力矩**，臂若伸开会砸桌。

#### 目标

单一写者；危险操作前可预测的安全姿态。

#### 备选方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A1 继续只用 Fibre | 厂商/原协议硬件节点 | 集成现成 | 与后续 CDC ASCII、调试工具冲突；难深度定制 |
| A2 纯脚本点动 | 无 ROS | 简单 | 难接视觉伺服与 TF |
| A3 **CDC 独占桥 + ROS** | bridge 独占 `/dev/ttyACM0`，对上发 joint_states，对下消化 Jog | 可观测、可与 Servo 对接 | 要自己处理超时、hold |

#### 选定：A3 + 强制 stow 流程

**技术路线**

1. `cdc_servo_bridge` 独占串口；Hub/跟随启动前检测 Fibre 进程。  
2. 跟随命令经 Servo → bridge，不直连多写者。  
3. 断电、停桥、会脱力的重启：**先 `stow.sh` 收到折叠位**再动进程。

**为何选它**

- 信息岗落地智能制造时，**设备独占与安全点**比算法更基础。  
- 把「记得别抢口」变成脚本契约，可审计。

**实现要点**

- 启动脚本显式互斥 Fibre。  
- 操作纪律写入 skill/规则：未见 ACM 不在伸出态杀桥。

**映射**：产线「一设备一主站」+ LOTO/回安全点思维。

### 步骤 B｜眼在手上标定：像素如何变成可伺服误差

#### 背景现象

相机在腕部，板在外部；未标定则「画面中心」与臂运动方向不一致。

#### 目标

得到 `link5_1_1 → camera`（相机不随 J6 转，effector 选 J5 壳体而非法兰）。

#### 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| B1 手工量尺估外参 | 快 | 误差大，难复现 |
| B2 眼在手外（相机固定） | 标定有时更稳 | 不符合「工具随末端」类比 |
| B3 **easy_handeye 眼在手上** | 社区成熟、与 ROS TF 结合好 | 需多姿态采集 |

#### 选定：B3

**技术路线**

1. 打印已知尺寸 ArUco（ORIGINAL id0，50 mm）。  
2. 固定板、腕部相机多姿态采样。  
3. Save 标定；跟随启动时自动发布手眼 TF。

**为何选它**

- 可重复、可进 TF 树，和后续光学误差定义一致。  
- effector 选 `link5_1_1` 与「J6 锁相机不转」的机械事实一致，避免标错链。

**映射**：多传感器时空标定是检测/导引项目的入场券。

---

### 步骤 C｜第一版视觉伺服：先 dry-run 再 LIVE

#### 背景现象

需要尽快看到「误差是否随板动」，但不能一上来就磕臂。

#### 目标

检测 → 期望位姿/光学误差 →（可选）真机。

#### 备选方案

| 方案 | 说明 |
|---|---|
| C1 开环示教再现 | 无视觉闭环 |
| C2 位置基视觉伺服（PBVS）整姿态 | 目标多，早期难调 |
| C3 **光学轴对准 + 距离（平移主任务）** | 误差三维、可解释 |
| C4 纯图像 IBVS | 对标定依赖不同，工程调试另一套 |

#### 选定：C3，并先 dry-run

**技术路线**

1. `aruco_detector` 出板位姿。  
2. tracker/解算器算「光心对准 + 目标距离」。  
3. `dry_run` 只看话题/HUD；确认后再 LIVE。  
4. 参数收敛到 `follow_live.yaml` 单一真源。

**为何选它**

- 与「喷枪瞄准」产品定义同构。  
- dry-run 降低试错成本，符合信息岗在 OT 旁路验证的习惯。

---

### 步骤 D｜人机与运维：Tracking Hub

#### 背景现象

命令行拉起 ROS+相机+桥+检测，门槛高；现场需要「看得到检没检到」。

#### 目标

一键入口 + 可观测状态机。

#### 备选方案

| 方案 | 缺点 |
|---|---|
| 只保留 launch | 无统一操作语义 |
| Web 大屏 | 对桌面样机过重 |
| **本地 OpenCV HUD + 脚本拉栈** | 轻、贴相机画面 |

#### 选定：桌面 Hub + `track_control`

**技术路线**

- 芯片：CAL/DET/TGT/SPRAY/CHG/MOV/RUN/SRV 等。  
- 按钮：开始跟随（远则先回 handeye）、回初始、收起、六轴拖动（经 bridge 话题，不占第二串口）。

**为何选它**

- 「可观测」是工程能力，不是 UI 好看。  
- 拖动与跟随互斥，避免双写。

---

### 步骤 E｜从「锁轴补丁」到清晰的关节策略

#### 背景现象

早期用锁 J4、软墙「遮丑」，对准像补丁；HUD 出现「只中心 / 中心+J4」等多模式，认知负担大。

#### 备选方案

| 方案 | 问题 |
|---|---|
| 继续锁轴当主策略 | 牺牲冗余，不可扩展 |
| 主任务强跟 6D 姿态 | 难稳、易绕圈 |
| **主任务只瞄准；J4 自由；J6 锁（减 CDC，非夹爪需求）** | 策略可讲清 |

#### 选定：后者，并删掉模式开关

**技术路线**

- 成功标准不变。  
- J6 锁：相机不绕光轴空转，减少无意义串口流量。  
- J4 自由：交给后续 WDLS 零空间偏好，而不是假墙。

**为何选它**

- ADR 明确：软限位只作安全边距，不作姿态主策略。  
- 减少操作维数，答辩时故事干净。

---

### 步骤 F｜绕圈与串口病：Hold + CDC Quiet

#### 背景现象

接近目标时末端**绕圈**；USB CDC **写超时**；若采用「弱 Hold 仍常发小增量」，通信更差。

#### 目标

数秒内进入保持并「静住」；保持期少写串口。

#### 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| F1 再加大阻尼/降速 | 实现简单 | 远处变肉；不治本 | 可作辅助 |
| F2 弱 Hold 常追 | 跟踪紧 | **加重 CDC** | 否决（定案） |
| F3 **滞回 Hold + 保持期停发 Jog** | 对齐通信现实 | 大死区会「钝」 | **采用** |
| F4 换更高端实时总线 | 治本通信 | 样机成本与周期不允许 | 远期 |

#### 选定：F3（可叠加 F1 的近区增益整形）

**技术路线**

1. 误差进入 `hold_xy/z` → phase=hold → 发零 Jog / 不写无效增量。  
2. 误差超过 `hold_resume_*` 且持续 `leave_hold_sec` → 再追。  
3. 丢检：按位姿年龄判定 LOST，短时 **coast**（速度衰减），避免 mux 心跳 q=0 造成抖失。

**为何选它**

- **控制与 OT 通信联合设计**：算法必须尊重现场总线能力。  
- 滞回避免 Hold 边界抖动。

**原理一句话**  
视觉伺服在耦合/近奇异附近易振荡；到位后从连续反馈改为死区保持，同时把总线从「高频微调」降为「安静」。

---

### 步骤 G｜解算器换代：Twist 伪逆 → WDLS + 零空间

#### 背景现象

笛卡尔 twist 交给 Servo 默认雅可比伪逆，姿态与绕圈仍像补丁；锁轴无法表达「多用 J5、少空转 J1」。

#### 目标

主任务保证喷枪瞄准；同一周期内整理冗余关节偏好。

#### 备选方案

| 方案 | 原理 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| G1 维持 Servo twist 伪逆 | \( \dot q = J^{+} v \) | 少代码 | 难加权偏好；补丁化 | 弃作主路径 |
| G2 离线轨迹规划再跟踪 | MoveIt plan | 平滑 | **跟不上人手持移动** | 不适跟随 |
| G3 操作空间阻抗/力控 | 力闭环 | 接触场景强 | 本机无力传感器主线 | 不做 |
| G4 **WDLS + 零空间投影** | 加权阻尼最小二乘；\( \dot q = \dot q_{\mathrm{task}} + N \dot q_{\mathrm{pref}} \) | 可调权重、同周期二次任务 | 要自写节点与调参 | **采用** |
| G5 学习策略（RL/IL） | 数据驱动 | 宣传点 | 样机数据少、难解释、难安全论证 | 研发过程可用 Agent，控制主路径不用 |

#### 选定：G4，独立节点，输出 JointJog

**技术路线**

1. 订阅目标总线位姿与质量。  
2. 在光学系算平移误差 → 笛卡尔速度（带近区增益、限速、quality 缩放）。  
3. WDLS 映到关节速度；零空间注入偏好（偏 J5、抑 J1）。  
4. 经 MoveIt Servo **JointJog** 下发；旧 twist tracker **退出命令路径**。  
5. Hold 时停发，配合 CDC Quiet。

**为何选 JointJog 而不是继续发 twist**

- 关节偏好与加权在关节空间更自然。  
- 与「J6 锁、分轴权重」一致。  
- Servo 仍负责底层安全与插值，解算器专注任务层。

**为何独立节点而不是埋在 ArUco tracker**

- 检测可换（板/充电头），解算器不应绑死某一种视觉。  
- 符合目标总线架构。

**原理（可写白板）**

- 主任务：3 维平移（对准 + 距离），六轴冗余。  
- WDLS：对病态雅可比阻尼，轴权重 \(W\) 抑制不想动的轴。  
- 零空间：\( N = I - J^{+} J \)，偏好速度投影后**不破坏主任务**（一阶意义下）。  
- **不是**「先对准再摆姿势」两段动作。

**映射**：产线冗余机构（7 轴、龙门+附加轴）上「主约束 + 工艺姿态偏好」的同一数学结构。

### 步骤 H｜目标总线：换物体不换大脑

#### 背景现象

若检测写死在 tracker 内，换螺母/杯/充电头就要改控制；HUD 与解算器双份逻辑。

#### 目标

检测器只产「位姿 + 质量」；mux 选源；解算器只认总线。

#### 备选方案

| 方案 | 缺点 |
|---|---|
| 每物体一套完整控制栈 | 爆炸 |
| 检测直接调解算器服务 | 耦合、难 LIVE 热切 |
| **话题总线 + follow_source** | 清晰 |

#### 选定：总线

**技术路线**

```
board_* ─┐
         ├─ mux(follow_source) → target_pose / target_quality → WDLS
charger_*┘
```

- 距离：板 `desired_marker_in_ee_z=0.20`；充电头 `desired_charger_in_ee_z=0.10`。  
- LIVE 中可切源（参数推到 mux + 解算器）。

**为何选它**

- 软件产品线思维：稳定内核，变化点在插件。  
- 为将来「学习型检测」留插槽：只替换前置节点。

### 步骤 I｜第二目标物体选型与检测路线

#### 背景现象与迭代

| 候选 | 结果 | 原因 |
|---|---|---|
| 六角螺母 | 搁置 | 小、暗、依赖轮廓，桌面干扰大 |
| 蓝盖透明杯 | 短时可用但脆 | 侧视圆度崩；键盘浅蓝抢色；凹坑扰深度 |
| 橙子 | 否决 | 色相与黄木纹桌重叠 |
| 灰绿方充电头 | **采用** | 不透明、与木纹 H 可分、几何近方 |

#### 检测备选

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 再上 ArUco 贴头顶 | 最稳 | 改物体属性 | 验证跟随可用；「日常物」说服力弱 |
| 深度学习检测 | 泛化 | 数据/部署/解释成本 | 总线预留，本轮不做 |
| **HSV + minAreaRect + 深度中位** | 可调、可解释、贴样机 | 光照与杂物敏感 | **本轮采用** |

#### 选定路线（充电头）

1. HSV 灰绿窗（桌面实测 H≈40，S 中低 → 窗要放宽）。  
2. 轮廓 `minAreaRect`，限制宽高比（侧视会到 ~1.6，阈放到 ~1.9）。  
3. 矩形填充率；边长反投影到米制，窗约 30–75 mm。  
4. 瞄准点：矩形中心；深度：邻域中位数。  
5. 发布 `/tracking/charger_{pose,quality,px}`。

**为何「硬跟充电头」仍有工程价值**

- 展示**可观测性驱动的物体选型**（Design for Vision）。  
- 展示参数与几何门控如何根据实机帧诊断迭代（aspect 阈值故事可讲）。

### 步骤 J｜质量门控、丢检与滤波

#### 背景现象

mux 在短暂丢检时发 q=0，若解算器把 q=0 当 LOST，会出现 DETECTED/LOST 闪烁，永远进不了 Hold。

#### 选定路线

- **位姿年龄**为 LOST 主判据；忽略 mux 的 q=0 心跳。  
- quality 门控与速度缩放仍用于「检到但很烂」。  
- 光学坐标低通（`opt_filter_alpha`）抑噪。  
- 短时 coast 衰减上一命令。

**为何**：状态机要区分「传感器静默」与「目标真丢」——工业检测触发同样问题。

### 步骤 K｜研运架构：双机 + Git + 文档即状态

#### 背景现象

重活在家里 Linux（臂、相机、ROS）；日常在单位 Windows。Local Agent 会话不能跨机器继承。

#### 备选

| 方案 | 结论 |
|---|---|
| 单位本地跑 ROS | 无臂、无相机，假闭环 |
| 桌面远控整机 GUI | 重、难脚本化 |
| **Tailscale + Cursor Remote SSH；真相在 Git；进度写 TODO** | 采用 |

**为何**：信息岗真实工作模式——算力/设备在机房或产线侧，人在办公网；**契约是仓库与文档，不是聊天记录**。

### 步骤 L｜AI Agent 工程方法（答辩加分项）

#### 不做的事

- 不让模型直接对真机下未审指令。  
- 不用「一次生成全部控制」替代可解释伺服。

#### 做的事（技术路线）

1. **Grill / 领域建模**：逼问到术语稳定 → `GLOSSARY.md`。  
2. **定案表 + ADR**：例如为何 WDLS、为何否决弱 Hold 常追。  
3. **实现**：按定案改节点、yaml、Hub。  
4. **实机诊断**：抓帧分析 HSV/宽高比；修阈值；重启检测。  
5. **防 Agent 误伤**：Hub 的 `pgrep` 曾把 Cursor 命令行误判为「Fibre 在跑 / HUD 已开」→ 收紧匹配规则（工程上「自动化脚本也要抗假阳性」）。

**选型原因**：Agent 擅长探索与改代码；**安全边界、验收、架构决策**必须留在工程师。这是可迁移到企业「AI 辅助研发」的正确姿势。

## 4. 端到端「我如何做一次跟随」操作叙事（可演示）

1. 臂上电，确认 `/dev/ttyACM0` 与 USB `1209:0d32`。  
2. 开 Tracking Hub（Servo + 相机 + CDC + 检测）。  
3. 默认源标定板；或切「充电头」。  
4. 点开始跟随：若偏离 handeye 太远，先回初始再 LIVE。  
5. 看 CHG/DET、AIM、SPRAY：对准且 Hold 则喷枪瞄准达成。  
6. 收工：停止收起 / `stow.sh`，再断电。

## 6. 口述总稿（约 6–8 分钟，可删减）

各位评委好，我是信息部门工程师。我用一个桌面六轴眼在手上跟随样机，说明我在智能制造方向能交付的软件与 AI Agent 能力。

**第一，问题怎么定。**  
我把任务收敛成「喷枪瞄准」：光心对准、距离达标。不把抓取、全姿态跟踪塞进第一期。这是需求工程：可验收、可分层。

**第二，底座怎么做。**  
CDC 独占写电机，和 Fibre 互斥；会脱力的操作前强制收起。这是 OT 纪律。然后做眼在手上标定，让像素误差进 TF，能伺服。

**第三，闭环怎么演进。**  
先 dry-run 再 LIVE；用 Hub 把检测与运动状态摊开。早期靠锁轴补丁，后来明确 J4 自由、J6 锁只为减负。接近目标绕圈、串口超时后，引入滞回 Hold 和 CDC 静默——**算法服从现场总线**，否决「弱 Hold 常追」。

**第四，解算怎么换代。**  
Servo 默认 twist 伪逆不够，我做成独立 WDLS 解算器：主任务瞄准，同周期零空间做关节偏好，JointJog 下发。检测与控制用目标总线解耦，第二物体从螺母、杯迭代到灰绿充电头，用可解释的颜色几何深度，而不是一上来上黑盒模型。

**第五，AI Agent 怎么用。**  
用 Agent 做 grill、写术语表和 ADR、改代码、对着实机帧查为何检不到；安全与验收我负责。远程用 Tailscale SSH，进度落 Git 与 TODO，避免智能只留在聊天窗口。

**收尾。**  
这不是产线认证产品，而是可运行的方法交卷：现场故障 → 架构决策 → 可插拔实现 → 可复现研运。谢谢。

## 7. 评委追问储备

**为什么不用强化学习做跟随？**  
主路径需要可解释、可限幅、可与 Hold/总线策略组合；样机数据不足以论证安全。学习检测可作为总线前插件，不推翻 WDLS 内核。

**为什么充电头不是贴码？**  
贴码更稳，但本轮要验证「非标记物 + 可插拔检测」。物体选型本身就是结论：对比度与几何要服从视觉。

**精度数字？**  
以进入 Hold、光心对准为阶段门；板 20 cm、充电头 10 cm。未锁定的毫米级指标不在答辩里充数。

**和公司数字化项目关系？**  
同类问题是「端侧感知相对位姿保持 + 可集成架构 + OT 友好」。我证明信息岗可以主导这类闭环的软件骨架与 AI 辅助工程方法。

**最大失败教训？**  
（1）锁轴当主策略会堵死演进；（2）忽略 CDC 能力会设计出「跟踪很紧但总线先死」；（3）自动化脚本的进程匹配会被 IDE 命令行误伤——生产脚本也要防假阳性。
